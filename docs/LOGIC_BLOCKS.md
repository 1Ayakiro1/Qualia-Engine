# Логические блоки Workspace

Это встроенные узлы движка, **не исполняемые модули**. Для них не нужны `.qmod`,
интерпретатор, сеть или отдельный процесс. Их конфигурация сохраняется вместе
с графом и переносится между воркспейсами, как конфигурация обычного узла.

## Добавление и отображение

- Explorer → **Логические блоки**: отдельный поиск и перетаскивание на canvas.
- Меню Add или ПКМ пустой области → **Добавить логический блок**.
- Иконка ветвления отличается от иконки модуля.
- Меню View независимо показывает/скрывает логические узлы и узлы модулей.
  Эти фильтры **только визуальные**: не выключают обработку, не удаляют связи.
  Провода к невидимым узлам не рисуются. Фильтры сохраняются локально.
- Чтобы остановить конкретный узел, выключите его `enabled` в Inspector.
  Это отличается от глобального «Скрыть модуль» в Explorer: тот переключатель
  по-прежнему останавливает экземпляры соответствующего установленного модуля.

## Виды блоков

| Блок | Настройка | Выходы |
|---|---|---|
| IF | Булево выражение | `true`, `false` |
| Фильтр | Булево выражение | `output` только при true |
| Выбор полей | Список верхнеуровневых ключей через запятую | `output` с выбранными полями |
| Проверка входа / выхода | JSON-схема | `valid`, `invalid` |
| Скрипт | Ограниченный язык маршрутизации | `output`, `true`, `false`, `valid`, `invalid` |

У всех блоков один вход `input`. Проверка схемы **не удаляет поля**; подключите
«Выбор полей», если нужно оставить только разрешённые ключи. Выход `invalid`
содержит исходные данные: не соединяйте его с вычислительным модулем, если
некорректные данные должны отбрасываться. Неподключённая ветка не передаёт данные.

Редактирование доступно в Inspector, Open, fullscreen и отдельном окне.
Кнопка теста проверяет JSON-пример **без отправки в рабочий граф**.

## Язык скриптов `host-logic-v1`

```text
if has(value, "score") and value.score >= 0.7 {
  emit true select(value, "score", "channel");
} else {
  drop;
}
```

В IF/Фильтре вводится только выражение, например:

```text
has(value, "score") and value.score >= 0.7 and not (value.channel == "C4")
```

- `value` — текущий вход; `value.field.nested` — доступ к полям объекта.
  Отсутствующее поле возвращает null; `has(value, "field")` отличает его от
  присутствующего поля со значением null.
- Скаляры: строки в двойных кавычках, числа (в том числе отрицательные),
  `true`, `false`, `null`. Сравнения: `==`, `!=`, `>`, `>=`, `<`, `<=`.
  Упорядочивание работает только для конечных чисел, без преобразования строк.
  Равенство предназначено для скаляров, не для структурного сравнения объектов.
- `and`, `or`, `not` (или `!`), скобки. AND/OR вычисляются с коротким замыканием.
  Ключевые слова пишутся строчными латинскими буквами.
- `select(object, "field", ...)` создаёт объект только с выбранными
  верхнеуровневыми полями. Отсутствующие поля пропускаются, вложенные значения
  передаются целиком. Для строгости дополнительно используйте схему.
- `if ... { ... } else { ... }`: допускается вложенность; ELSE необязателен.
- `emit port expression;` отправляет результат в объявленный выход.
- `drop;` прекращает выполнение всего скрипта и отбрасывает все его результаты,
  в том числе предшествующие emit. `//` — комментарий до конца строки.
- Нет присваиваний, циклов, импортов, файлов, сети, запуска программ или eval.
  Ошибка синтаксиса/типа останавливает обработку **этого сообщения**, показывает
  `logic error` и не передаёт частичные результаты.

Лимиты: 8192 символа, 1024 токена, 16 уровней блоков, 32 уровня разбора выражений,
64 уровня вычисления, 256 инструкций и 16 emit на вход. Маршрутизатор уменьшает
`hops` на каждом ребре (максимум 32) и ограничивает один dispatch 512 доставками.
Это контрольные данные, не hard-real-time обработка EEG.

## Схемы входов и выходов

Блок проверки принимает ту же схему, что manifest `portSchemas`:

```json
{
  "type": "object",
  "properties": {
    "score": {"type": "number"},
    "channel": {"type": "string"}
  },
  "required": ["score"],
  "additionalProperties": false
}
```

Поддерживается **не полный JSON Schema**, а небольшой строгий контракт:
`type` (`any`, `null`, `boolean`, `number`, `string`, `array`, `object`),
`properties`, `required`, `additionalProperties`, `items`. Неизвестные ключевые
слова отклоняются. Без `additionalProperties: false` лишние ключи разрешены;
без `required` поля необязательны. Лимит глубины схемы — 8, свойств — 64,
проверяемого объекта — 256 ключей, массива с объявленной схемой — 4096 элементов.
`any` и порт без схемы не ограничивают структуру; общий лимит кадра действует всегда.

Для модуля схемы задаются по стабильным ID портов:

```json
"portSchemas": {
  "inputs": {"input": {"type": "number"}},
  "outputs": {"output": {"type": "number"}}
}
```

Host проверяет выход установленного процесса до маршрутизации и вход целевого
процесса до отправки. Некорректные сообщения отбрасываются, без приведения типов.
Типы портов из Inspector также проверяются на входе и выходе. Старые пакеты без
`portSchemas` совместимы; строгий allowlist данных автор задаёт явно.
