# Локальные C++-модули Qualia Engine

## Что реализовано

Модуль — самостоятельная программа на C++17, упакованная в `.qmod`.
**Каждый узел Workspace запускает свой процесс и имеет своё состояние.**
Модули не загружаются как `.so` в процесс движка и не становятся частью монолита.
Движок отвечает за граф, маршрутизацию сообщений, сохранение параметров и окна;
модуль отвечает за обработку данных и прикладную логику.

Inspector, Open, fullscreen и отдельное окно — разные представления **того же
экземпляра**. Открытие второго окна не запускает ещё один вычислительный модуль.
Кнопки отправляют события, а не сохраняют `true` как параметр. Результаты `state`
живут отдельно от параметров и не попадают в файл Workspace.

Первая версия поддерживает **Linux x64**, CMake и C++17. Python 3 нужен только
для SDK-команд и упаковки, а не для выполнения установленного модуля.
Сборка не скачивает зависимости: JSON-библиотека включена в SDK.

## Быстрый старт через интерфейс

1. Откройте Workspace и нажмите **+** в Explorer.
2. Выберите **Создать локально** и укажите пустую папку проекта.
3. В ней появятся `main.cpp`, `manifest.json`, `CMakeLists.txt`, `qmod.py` и `include/`.
4. Выполните в папке проекта:

   ```bash
   python3 qmod.py check .
   python3 qmod.py build .
   ```

5. Пакет появится в `dist/local-gain-0.1.0.qmod`.
6. В Explorer выберите **Добавить локально (.qmod)**, выберите пакет и подтвердите доверие.
7. Перетащите Local Gain из библиотеки на граф, откройте **Open**.
8. Установите Gain = 2, Sample = 3 и нажмите Run: Result станет 6.

Пакет не требует входа в аккаунт, Supabase или Marketplace.
Для проверки без компилятора можно сразу установить готовый пример
`builds/modules/local-gain-0.1.0.qmod`.
Действия **Создать онлайн** и **Добавить онлайн** остаются отдельными путями:
авторский черновик и переход в Marketplace. Онлайн-каталог сейчас добавляет
metadata, **не скачивает и не запускает удалённые бинарные пакеты**.

## SDK из репозитория

```bash
python3 app/assets/module_sdk/qmod.py create /path/to/empty/project
python3 /path/to/empty/project/qmod.py check /path/to/empty/project
python3 /path/to/empty/project/qmod.py build /path/to/empty/project
```

Системные инструменты: Python 3, CMake >= 3.21 и компилятор C++17.
Измените `id`, `name`, `description` и `version` в манифесте для своего модуля.
ID должен быть уникальным (`my-eeg-filter`), версия имеет вид `0.1.0`.
IDs портов и контролов — стабильные идентификаторы, а не отображаемые названия.

## Структура `.qmod`

Это ZIP с **несжатыми файлами (ZIP STORE)** и расширением `.qmod`:

```text
manifest.json
bin/module
assets/...        # необязательно
```

Обязательные поля манифеста:

```json
{
  "format": "qualia-module",
  "schemaVersion": 1,
  "id": "my-eeg-filter",
  "name": "My EEG Filter",
  "version": "0.1.0",
  "runtime": "native-process-v1",
  "platform": "linux-x64",
  "entrypoint": "bin/module",
  "ports": {"inputs": ["input"], "outputs": ["output"]},
  "ui": [
    {"id": "gain", "type": "number", "label": "Gain", "default": 1},
    {"id": "run", "type": "button", "label": "Run"},
    {"id": "result", "type": "label", "label": "Result"}
  ]
}
```

Поддерживаются существующие UI-контролы: `slider`, `toggle`, `select`, `text`,
`number`, `button`, `label`. Host рисует их сам. `label` отображает выходное
состояние из `state`; остальные значения — параметры экземпляра, кроме `button`.
Произвольный Flutter/HTML-код не выполняется.

Ограничения: до 64 контролов, 16 входов и 16 выходов, 256 файлов и 64 MiB на
пакет. Сжатые архивы, symlinks, пути за пределами пакета, дубли путей,
шифрование и бинарники другой архитектуры отклоняются.
Установка атомарная, по SHA-256 пакета в application support directory `qmod/`.
Пути к executable из документа Workspace не принимаются.

## Написание логики

Наследуйте `qualia::Module` из `include/qualia.hpp`:

```cpp
#include "qualia.hpp"

class Filter final : public qualia::Module {
  double gain_ = 1.0;
 public:
  void initialize(const qualia::Json& init) override {
    parameters(init.at("parameters"));
  }
  void parameters(const qualia::Json& values) override {
    gain_ = values.value("gain", 1.0);
  }
  void input(const std::string& port, const qualia::Json& value) override {
    if (port != "input" || !value.is_number()) return;
    const double result = value.get<double>() * gain_;
    state({{"result", result}});
    emit("output", result);
  }
  void event(const std::string& id, const qualia::Json&) override {
    if (id == "run") state({{"result", "Ready"}});
  }
};
int main() { Filter filter; return filter.run(); }
```

Экземпляр создаётся один раз в своём процессе. Не используйте глобальные файлы
или фиксированные порты для состояния экземпляров: это нарушит независимость,
даже если память процессов изолирована.

Для проверки маршрутизации соедините output первого Local Gain с input второго.
Если gain первого = 2, sample = 3, gain второго = 4, Run на первом даст 6 на
первом и 24 на втором. Переименование отображаемых портов не меняет маршрутизацию.

## Протокол `native-process-v1`

IPC — JSON Lines через stdin/stdout процесса; одна UTF-8 JSON-запись на строку.
**stdout — только протокол**, диагностика — stderr. SDK обрабатывает протокол
сам; прямой его реализации обычно не требуется.

| Направление | Сообщение | Назначение |
|---|---|---|
| module → host | `ready`, `protocol: 1` | Подтверждение готовности |
| host → module | `init`, `instanceId`, `parameters` | Начальная конфигурация |
| host → module | `parameters`, `values` | Полный актуальный набор параметров |
| host → module | `event`, `id`, `value` | Нажатие кнопки |
| host → module | `input`, `port`, `value`, `hops` | Данные связанного выхода |
| module → host | `state`, `values` | Выходные значения label-контролов |
| module → host | `output`, `port`, `value`, `hops` | Данные выходного порта |

Значения портов — JSON: число, строка, bool, массив, объект или null.
Тип входа, заданный в Inspector, проверяется перед маршрутизацией.
Контролы и порты неизвестных IDs не становятся частью интерфейса/графа.
До 64 KiB на кадр, до 1000 выходных сообщений/с на экземпляр, ограниченная
очередь записи. Пятисекундный timeout handshake останавливает неготовый процесс.
SDK переносит бюджет `hops` по обработке входа; host уменьшает его при маршрутизации.
Граф также запрещает processing-циклы.

Это **не hard-real-time транспорт EEG**: для больших потоков понадобится
версионированный бинарный SampleBlock/shared-memory канал с backpressure.
Для первого SDK используйте небольшие JSON-блоки и обрабатывайте их внутри C++.
Контракт не заменяет legacy `IModule` встроенного pipeline.

## Жизненный цикл и обновления

- Добавление установленного узла запускает процесс с сохранёнными параметрами.
- Окна и Inspector не владеют вычислениями; закрытие окна не останавливает узел.
- Выключение `enabled`, удаление узла, удаление из библиотеки и переключение
  Workspace завершают процессы соответствующих узлов.
- Авария модуля или ошибка протокола останавливает только его экземпляр;
  host не перезапускает аварийный код в бесконечном цикле.
- Для повторного запуска выключите и включите экземпляр через Inspector.
- При возвращении в Workspace экземпляры создаются заново. Сохраняются
  параметры, но не произвольная память C++-процесса и не предыдущие результаты.
- Для обновления измените version, соберите и добавьте новый `.qmod`.
  Старый узел сохраняет привязку к своему hash/версии; замена модуля — явное
  действие. Несколько версий остаются доступными для старых Workspace.
- Обмен `.qualia-workspace` не переносит executable и не выдаёт доверие.
  Получатель сначала устанавливает нужный `.qmod`; недоступная локальная
  зависимость отклоняет импорт, без попытки получить её из онлайн-каталога.
- Удаление из библиотеки прекращает запуск, но оставляет файлы установки,
  чтобы не удалять данные или версии, нужные другим проектам.

## Безопасность и границы

**Отдельный процесс — изоляция памяти/аварий, а не защитная песочница.**
Нативный модуль работает с правами вашего пользователя и может обращаться к
файлам, сети и устройствам напрямую. В v1 нет capability enforcement, подписей,
ограничений CPU/RAM, защиты от намеренно вредоносного кода и process-tree sandbox.
Если модуль сам создаёт дочерние процессы, он должен завершать их самостоятельно.
Устанавливайте только доверенный код. Не проверяйте неизвестные пакеты на
основной системе; используйте отдельную VM/контейнер.

Автоматического `dev`/watch, собственного GUI-рендера, marketplace-поставки
бинарников и Windows/macOS-пакетов в первом SDK нет. Это отдельные расширения
контракта, а не скрытые зависимости текущего локального пути.

SDK включает nlohmann/json 3.11.3 (MIT); текст лицензии сохранён в `include/json.hpp`.
